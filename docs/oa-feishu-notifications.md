# OA 飞书提醒

生产 Worker 复用既有飞书企业自建应用，不增加聊天读取权限。应用需开启机器人能力、具备 `im:message:send_as_bot`（或已有等效消息发送权限），并对对应成员可用。参考[飞书发送消息 API](https://open.feishu.cn/document/server-docs/im-v1/message/create)和[官方 SDK 的 UUID 去重说明](https://pkg.go.dev/github.com/larksuite/oapi-sdk-go/v3/service/im/v1#CreateMessageReqBody)。

当前处理人收到待办提醒；多人流转和多人审批通知当前阶段的未处理成员。退回时通知申请人，重新提交产生新一轮提醒。消息只包含节点及 OA 链接，正文与处理权限仍由 OA 控制。

`migrations/oa/0001_feishu_notifications.sql` 是通知运行状态的增量迁移，应用于现有生产 D1 `34af7e92-7da5-47cd-b7c0-1270e157c0e6`。首次记录审批事件水位，不补发历史记录。通知表独立于既有业务迁移链；旧的导出工具不包含通知水位和发件记录，后续迁移必须额外转移这两张运行状态表，避免重复提醒。

配置：保留所有已有变量和绑定，增加 `FEISHU_NOTIFICATIONS_ENABLED=true`，并启用每分钟 Cron `* * * * *`。`worker/standalone.ts` 转发 scheduled 事件。提交后尝试处理通知；Cron 在无人打开网页时继续处理队列。每批最多扫描 5 个事件、发送 5 条消息，大批接收人会分批送达。迁移冻结期间不启动新一轮通知处理。

通知按申请、提交轮次、节点和成员稳定身份去重。D1 持久队列及发送租约防止并发重复；发送前重新核对当前待办、成员有效状态、飞书应用和企业身份。已处理任务自动跳过。网络失败使用同一 UUID 重试，最多 6 次；超过 50 分钟的未确认发送停止自动重试，避免越过飞书的一小时去重窗口。

管理员在 OA「飞书提醒」查看计数、错误代码和本人测试结果。测试仅发给当前管理员，五分钟内合并重复点击。`sent` 表示飞书 API 已接收消息，并不表示成员已阅读。

回退时可将 `FEISHU_NOTIFICATIONS_ENABLED=false` 或回退 Worker 代码，保留通知表及水位。不要删除业务记录或重置通知队列来解决权限问题。修复飞书权限后，先发送本人测试；对失败记录核实是否已送达，再决定是否重试。
