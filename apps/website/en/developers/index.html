01 / CONNECT

Quick start

Check your installed delivery version first. Keep the workbench process running; the graphical interface is optional. The default service address is http://127.0.0.1:8085.

Local interfaces

These HTTP JSON interfaces are provided by the installed client software. They do not require an account or API key by default. Remote access, cross-origin websites and public authentication are outside this interface scope.

Starting the service
ProductVersionRun from the installed program directory
OmindOS Navigation0.2.0-preview.8./omindos workbench
OmindOS Manipulation0.3.1./OmindOS-Workbench --no-browser

Use Content-Type: application/json for POST requests. Both programs use port 8085 by default. Run them separately, or pass --port 8086 to the manipulation program and update your client URL.

cURL
curl --fail-with-body http://127.0.0.1:8085/v1/workbench-state

02 / NAVIGATION

Navigation profiles

Register robot parameters, preserve versions and retrieve a profile by ID. Identical submissions return the same ID; changed parameters create a new version. Registration does not enable physical motors.

Profile endpoints · Navigation 0.2.0-preview.8
MethodEndpointDescription
POST/v1/robot-profilesBody: complete robot profile; success returns HTTP 201 and profile_id
GET/v1/robot-profiles/{profile_id}Retrieve a saved version using the complete profile ID
Profile request body
FieldMeaning
robot_idRobot identifier
kinematics.urdf_xmlURDF XML text
dynamics.jointsMotor and transmission parameters keyed by joint name; use a complete profile exported from the workbench

Export robot-parameters.json from the workbench first. Do not fill unknown motor calibration parameters with estimated values. Replace PROFILE_ID below with the complete profile_id returned by POST.

cURL
curl --fail-with-body \
  -X POST http://127.0.0.1:8085/v1/robot-profiles \
  -H 'Content-Type: application/json' \
  --data-binary @robot-parameters.json

curl --fail-with-body \
  http://127.0.0.1:8085/v1/robot-profiles/PROFILE_ID

The success response includes profile_id, robot_id and joint_names. runtime_applied and hardware_validated are false: the profile is stored, not applied to a physical controller.

03 / MANIPULATION

Manipulation

For OmindOS Manipulation 0.3.1: model queries, dual-arm and waist planning, and geometric navigation for differential or omnidirectional bases. The supplied RM75 models use left_tool0 and right_tool0 as TCP frames. Use the mapping returned by the selected model.

Planning requests: fields and units
Planning request fields
FieldMeaning

04 / EXAMPLES

Examples

Read manipulation workbench state

This Python example uses only the standard library. It reads state, the model catalog and navigation configuration without changing workbench parameters.

Python
import json
from urllib.request import urlopen

base_url = "http://127.0.0.1:8085"
for endpoint in ("/v1/workbench-state", "/v1/workbench-models",
                 "/v1/navigation-config"):
    with urlopen(base_url + endpoint, timeout=10) as response:
        print(endpoint, json.load(response))

Register a navigation profile

Prepare robot-parameters.json exported from the workbench before running this example. The profile is stored in the running program’s data directory.

Python
import json
from pathlib import Path
from urllib.request import Request, urlopen

payload = Path("robot-parameters.json").read_bytes()
request = Request(
    "http://127.0.0.1:8085/v1/robot-profiles",
    data=payload,
    headers={"Content-Type": "application/json"},
    method="POST",
)
with urlopen(request, timeout=10) as response:
    result = json.load(response)
print(result["profile_id"])

Submit a prepared planning request

Prepare planning-request.json using the fields above and the current model’s profile and mapping. Poll using the returned task_id; HTTP success does not mean planning is complete.

cURL
curl --fail-with-body \
  -X POST http://127.0.0.1:8085/v1/planning-start \
  -H 'Content-Type: application/json' \
  --data-binary @planning-request.json

curl --fail-with-body \
  http://127.0.0.1:8085/v1/planning-task/TASK_ID

05 / TASK STATES

States and errors

Planning: running → succeeded / failed / canceled. A successful submission only creates the task. Continue querying its state.

Navigation: planning, navigating, aligning, parking. Navigation-only success ends at parked. A task with follow-up manipulation enters manipulation_planning and finishes at succeeded.

Keep polling navigation tasks

Query the task every 0.1–0.5 seconds. A gap longer than 3 seconds stops the task. For navigation-only success, result is null: read navigation. Do not continue using a partial path after failure or cancellation.

Common HTTP statuses
HTTPAction
400Invalid request; inspect error. Asynchronous validation may also return status=failed
403Local same-origin check failed; use a local client and 127.0.0.1
404Requested profile, model or task is missing; check the full ID
413Invalid body size or transfer encoding; profile request limit: 2 MiB
415Incorrect POST content type; set Content-Type: application/json
423Software stop, task exclusion or state interlock; read current state and do not automatically retry motion

Stop and reset

Send {"engaged":true} to /v1/workbench-stop to engage the software stop. Before resetting, read the current motion_epoch and pass that integer as expected_epoch with engaged: false. Reset does not resume a task. A software stop is not a hardware emergency stop.

06 / COMPATIBILITY

Versions and scope

Version compatibility
Documentation versionDocumented scopeRuntime
Navigation 0.2.0-preview.8Robot profile registration and retrieval; preview release, physical hardware not validatedUbuntu 22.04 / 24.04 x86_64; installed workbench and Docker Engine
Manipulation 0.3.1Local kinematics, path planning, conservative sampled collision and geometric navigation simulationUbuntu 22.04 / 24.04 x86_64; installed workbench, no separate ROS or Docker

The manipulation version covers the documented local software functions. Physical drivers, dynamics, force control, continuous collision and payload collision are outside its validated scope. The navigation profile API does not imply that a quadruped has been calibrated.

Confirm the software version, robot model, parameters and task environment before integration.
