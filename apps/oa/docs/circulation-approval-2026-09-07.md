# 流转审批（2026-09-07）

OA 新增独立的「流转审批」类型，用于自选人员处理一般事项。入口为「新建审核」中的「流转审批」，列表也提供同名筛选。按用户要求，日常新建、流程说明与类型筛选仅显示技术审核、采购审核、劳务报酬、流转审批四类；保密签署仍由首次准入页办理，历史签署记录和待办恢复路径保留。

## 使用规则

| 流转对象 | 审批人 | 完成方式 |
| --- | --- | --- |
| 选择一人或多人 | 留空 | 全部流转对象确认已处理后归档 |
| 留空 | 选择一人或多人 | 全部审批人同意后归档 |
| 选择一人或多人 | 选择一人或多人 | 全部流转对象确认后进入审批，全部审批人同意后归档 |

两栏可分别多选，每栏最多 50 人；提交时至少选择一栏并填写事项标题与内容。候选人为已完成 OA 准入的有效成员，不限部门或原审核角色。申请人可以选择自己接收流转，不能审批自己的申请。同一位其他成员可兼任流转对象与审批人，但必须分别完成两次操作。

同一环节内不限制处理顺序，各人的确认或审批独立记录。尚未处理的指定人员会看到「待我处理」。当前处理人可填写意见并退回；申请人修改重提时重新开始流转，旧事件与不可变版本保留。草稿不向所选人员开放。

## 实现与兼容

- 在原有审批记录的 JSON 材料中存储两组成员与两组处理记录，无数据库迁移。
- 服务端根据成员 ID 重新解析实名账户，忽略客户端提供的姓名、账户主体与已完成决策。
- 每次处理校验当前成员主体与准入；事务内继续校验操作者有效性，使用原有并发版本保护与原子事件、材料版本写入。
- 复用现有详情、PDF、飞书归档与撤回/退回/作废机制；原四类申请的审核权限与职责约束保持原规则。
- 本次不发送测试通知，不在正式数据库创建虚构申请。

## 验证

17 项新增路由集成测试使用本地 SQLite、实际 Drizzle 查询、所有现有迁移与触发器，覆盖三种模式、普通成员多选乱序处理、非法与重复选择、身份伪造、草稿隐私、越权、同人双环节、退回重提、撤回修改、主体变更、成员撤销竞态、并发操作与 PDF 完整性。完整套件共 238 项通过，构建、TypeScript 和 ESLint 通过；ESLint 仅有原有警告。
